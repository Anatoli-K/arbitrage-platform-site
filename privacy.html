How Arbitrage Platform handles data in the owner's personal reporting workflow.

1. Application and operator

Arbitrage Platform is a personal application maintained by Anatoli-K. It collects advertising reports and is being connected to selected Google spreadsheets for the account owner's reporting workflow.

This policy applies to the application's Google integration and these informational website pages. It will be updated when the application's use of Google data changes.

2. Google data accessed

The application requests access to files the user explicitly selects and authorizes through Google. Depending on the selected reporting spreadsheet, this can include:

  • File and sheet identifiers, names and spreadsheet structure.
  • Cell values, formulas, number formats and chart definitions needed for the reporting workflow.
  • Google authorization credentials that allow the application to use the granted access, including while the user is not present.

The file permission allows reading and updating selected files. The integration supports spreadsheet inspection and optional updates. The account owner requests each update through the private Telegram bot and chooses a reporting mode before it starts.

3. Purpose and limits of use

Google spreadsheet data is used to inspect reporting sheets, import the owner's advertising reports, apply the selected reporting mode and generate images of requested spreadsheet areas, including the dashboard, summaries and campaign lists. The owner can request these images separately without updating the spreadsheet. After the owner confirms a prepared plan, the application can also send campaign status and budget changes calculated in the selected spreadsheet to Meta's Facebook Marketing API. Google user data is not sold, used for advertising profiles or used to train general-purpose artificial intelligence models.

The application's use and transfer of information received from Google APIs must follow the Google API Services User Data Policy, including its Limited Use requirements.

4. Storage and protection

Authorization credentials are stored on the operator's private server outside the public source repository, with access restricted through operating-system permissions. The private server also stores reporting data, private spreadsheet inspection snapshots, recovery copies for updates, generated dashboard images, prepared campaign change plans and their execution results.

Credentials, spreadsheet contents and report files are not included in this public website or its repository. Server backups may contain copies of locally stored data and authorization credentials.

5. Services involved

Google hosts the selected spreadsheets and processes authorization, API requests and exports of requested areas. When the account owner requests an update or screenshots, the resulting images are sent to the owner's configured private Telegram chat. Telegram therefore processes the spreadsheet information visible in those images, as well as commands, progress messages and completion notifications. Google authorization credentials are not sent to Telegram.

When the owner explicitly confirms campaign changes, Meta receives the relevant advertising account and campaign identifiers and requested status or budget settings. Telegram receives confirmation summaries and requested error details. Google authorization credentials are not sent to Meta.

GitHub hosts these informational website pages and may process technical request information, including IP addresses, for security and service operation. The website's own code contains no analytics scripts, cookies, sign-in forms or advertising trackers.

These services also process information under their own policies: Google Privacy Policy, Telegram Privacy Policy and GitHub Privacy Statement.

6. Retention and deletion

Locally stored reports and credentials remain under the operator's control until they are overwritten or removed. There is no promised automatic deletion period. The account owner can delete locally stored inspection data and credentials from their server and manage backup copies separately.

Revoking Google access prevents further authorized Google requests once the revocation takes effect. It does not automatically erase existing local reports, inspection snapshots or backups.

7. Revoking Google access

The account owner can review or revoke the application's access in Google Account connections. A new authorization is required to reconnect after access has been revoked.

8. Contact

The operator is Anatoli-K. General support and questions about this policy can be raised through the website repository's GitHub Issues.

Issues are public. Do not post private spreadsheet contents, reports or authorization credentials there. The account owner manages private data and access directly on their own server.
